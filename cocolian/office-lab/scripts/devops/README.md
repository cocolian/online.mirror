# 自动构建与部署

这里提供检测 GitHub main 分支变更、编译渲染服务、构建镜像和验证部署的实现。部署方需要按自己的环境配置工作目录、镜像仓库、集群访问权限和服务入口；真实部署信息保存在仓库外。

## 按模块发布

| 变更来源 | 对应模块 |
| --- | --- |
| 门户源码 | WOPI 与文档门户 |
| 渲染源码 | 在线编辑服务、Word 兼容配置实例、文档转换服务 |
| 渲染部署配置 | 对应渲染服务镜像与运行配置 |

监听器主动检测远程提交，经过防抖后触发发布。一次运行记录所用的精确源码提交；多仓库同时变更时合并发布范围。未变化的编译结果可复用，实际触发条件和配置字段见 `watch.py` 与 `release.py`。

## 发布流程

1. 检出并锁定源码版本，串行使用构建缓存。
2. 增量编译，运行通用字体和部署字体配置下的排版回归。
3. 构建运行镜像，推送到部署方配置的镜像仓库并核对摘要。
4. 启动隔离候选实例，检查字体、服务启动和合成文档转换。
5. 按不可变镜像摘要更新选中模块，检查编辑、保存及转换。
6. 核对非目标模块状态，记录发布或回退结果。

候选实例不接入生产 Service。发布失败时保留原有文档卷和凭据，并根据运行前保存的模板回退；检测到并发配置修改时停止覆盖并记录原因。

## 部署前配置

- 根据目标环境调整服务模板、构建目录、资源限制、命名空间与网络入口。
- 使用仓库外的私有配置提供镜像仓库地址、认证、集群凭据和实际机器路径。
- 为自动发布分配必要权限，并为本环境维护镜像与部署模板备份。
- 自行提供有权使用的字体；字体清单记录校验值，字体二进制不提交。
- 保持传输与镜像仓库的 TLS 校验，证书私钥及登录凭据保存在私有位置。

目录中的 systemd 文件是部署实现参考，安装前应检查执行用户、目录、依赖和资源限制。不要把某个环境的模板直接当作通用安装命令执行。

## 验证与记录

- `test_release.py`：发布范围、字体校验和回退等逻辑测试。
- `verify.py`：服务发现、编辑、保存和转换检查。
- `office-fonts-manifest.json`：部署字体文件名及校验值。
- `release.py`：构建、镜像发布、候选检查与部署。
- `watch.py`：提交检测、防抖与运行状态管理。

构建日志、实际部署模板、认证配置、集群快照、私有样本和生成 PDF 应保存于私有工作目录。对外反馈时只提供经过检查的必要信息及可公开的最小复现案例。
