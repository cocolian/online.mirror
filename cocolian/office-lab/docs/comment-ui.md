# Writer 批注界面

Writer 区分修订和评论：插入、删除等修订直接由原生编辑器在原文中显示，通过“审阅”工具栏、正文上下文菜单或管理修订对话框接受/拒绝；右侧仅显示评论及回复，不把修订表或实时修订回调转换成评论卡片。原生修订表仍可供 AI 审阅读取，接受、拒绝及撤销继续走原生命令和既有 AI 审阅关联流程。

评论采用简洁的页边样式：作者、正文，只有当前选中的卡片显示左侧强调线，移除卡片阴影和头像，保留折叠讨论的计数。未选中时边框透明，保留相同宽度，切换选择不改变文字或卡片位置；悬浮本身不显示强调线。高对比度模式也仅强调选中的卡片。默认只显示作者和内容。时间、解决对勾和“⋮”只在悬浮或键盘聚焦时显示。它们保留布局空间，因此显示时不会移动后续评论。触屏没有悬浮，操作保持可见；菜单展开后也持续显示当前评论的操作。

对勾复用原生解决/重新打开批注命令；修改、回复、删除、线程操作及导航仍在原生菜单中。按钮遵循当前编辑权限、作者权限和宿主的 Hide_Command/HideChangeTrackingControls 设置，解决状态变化后同步更新无障碍名称与按下状态。菜单支持 Enter/Space，键盘跳转到批注时聚焦菜单。表格及演示文稿保留原有视觉样式。

## 验证

在环境中安全提供 `LAB_KEY`，并安装 Playwright 与 Chrome 后运行：

```sh
python cocolian/office-lab/scripts/verify-comment-style.py --base https://office.cocolian.cn --output comment-style-validation
```

脚本只新建合成测试文档，验证默认/悬浮显示、卡片高度不变、菜单展开状态、修改与回复、键盘解决和重新打开、宿主命令隐藏、只读切换、删除回复、WOPI 保存和刷新。输出截图与结果，不打印登录密钥。候选代码可用 `--candidate` 指向包含 `candidate-methods.json` 和 `online/browser/css/cool.css` 的临时构建目录；正式验收不替换浏览器资源。

## 初始缩放与已有浏览器缓存

桌面 Writer 每次打开文档均展开左侧导航，保留大纲、搜索和会话入口；其他文档类型沿用各自的偏好。页面在导航/标尺右侧保留 16 CSS 像素间距并靠左排列，不随窗口余量居中。该位置通过统一视图坐标实现，文档、光标、标尺和批注保持一致；宽页面仍可横向滚动，手机和交互预览保留原有居中规则。`test_writer_layout.cjs` 覆盖不同窗口、缩放、屏幕像素比、批注可见性、混合方向页面和导航初始状态。

Writer 首次打开按实际文档画布（扣除大纲/会话和属性栏）适配，并为已有批注留出完整宽度和间距，自动适配最多 100%。手机不预留桌面批注栏，手动缩放仍可超过 100%。`test_writer_zoom.cjs` 覆盖已有批注、宽屏上限、窄屏、移动端及手动缩放保持。

增量构建目录是源码导出，不含 `.git`。每次编辑器构建必须将真实源码提交写入 `dist_git_hash`，重新生成 `config_version.h` 并验证；否则服务端继续把变化后的脚本和样式放在相同地址下缓存 128 天。发布后检查两个编辑器入口均使用本次版本号。验收应同时检查新会话和已缓存旧资源的现有页面，不能仅凭无缓存会话的结果判定普通刷新有效。

## 批注与修订定位

Writer 右侧的评论按文档顺序排列。点击卡片只切换选中状态和展开其内容，不以选中锚点重新排列整列，也不单独把选中卡片挪到其他卡片上。滚动以布局完成后的卡片位置为准；超出文档视口的部分被裁剪，不能覆盖工具栏或拦截其点击。

AI 审阅定期读取原生修订表时，不创建或重建右侧卡片，不改变评论选择，也不修改原始修订数据。评论数据变化时按 ID 恢复原来的选择。编辑中的卡片不被后台刷新销毁。回复导航保留被点击的回复作为展开目标。

回归覆盖修订表及实时回调均不生成 Writer 卡片、原始修订数据不变、正常评论事件、连续切换、周期刷新、回复目标、编辑保护及工具栏边界；其他文档类型仍保留其既有处理。运行 `node --test cocolian/office-lab/scripts/devops/test_comment_navigation.cjs`；发布构建在 TypeScript/ESLint 编译通过后执行此测试。
